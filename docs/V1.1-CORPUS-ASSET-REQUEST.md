# V1.1 Corpus Asset Request

Licensed evaluation binaries are required before `BROAD_DOCUMENT_GA_READY` can become true.

Do **not** email document contents into tickets/logs. Place files under a secure asset root and run intake.

## Required deliveries (minimum)

| # | Document class | Suggested relative path |
|---|----------------|-------------------------|
| 1–3 | Native PDF technical specifications | `native/native_tech_spec_00N.pdf` |
| 4–6 | Scanned PDF technical specifications | `scanned/scanned_tech_spec_00N.pdf` |
| 7–9 | DOCX technical specifications | `docx/docx_tech_spec_00N.docx` |
| 10–12 | Table-heavy technical documents | `table/table_heavy_spec_00N.pdf` (or `.docx`) |
| 13 | Company certificate | `knowledge/certificate_001.pdf` |
| 14 | Product datasheet | `knowledge/datasheet_001.pdf` |
| 15 | Additional company/product evidence | `knowledge/evidence_001.pdf` |

## Per-file metadata checklist

For each file provide:

- filename
- document type / purpose
- usage permission (internal evaluation? commercial evaluation?)
- source / provenance
- contains personal data? (yes/no/unknown)
- contains confidential data? (yes/no/unknown)
- may be retained for evaluation corpus?
- may be redistributed? (almost always no)

## License statuses accepted for release metrics

- `APPROVED_INTERNAL_EVALUATION`
- `APPROVED_COMMERCIAL_EVALUATION`
- `PUBLIC_DOMAIN`
- `OPEN_LICENSE`

`PENDING`, `RESTRICTED`, and `REJECTED` are excluded from release quality gates.

## After delivery

```bash
NANOBASE_CORPUS_ASSET_ROOT=/secure/path/to/corpus \
python3 scripts/corpus_intake.py \
  --manifest-dir evaluation/corpus/manifests \
  --asset-root /secure/path/to/corpus \
  --write-proposed-manifest-patches \
  --output /tmp/nanobase-corpus/intake-report.json
```

Intake is read-only: it does not move binaries into git.
